# 低多边形类魂合作战斗 Demo

一个用 Godot 4.7 制作的玩法验证 Demo：类魂战斗 + 四人合作 + 可破坏地形。

**这是一个 Demo，不是完整游戏。** 具体做到什么程度、哪些没做，
在下面的「当前完成度」和 `docs/测试记录.md` 里有如实说明。

---

## 一、环境要求

| 工具 | 版本 | 本机路径（示例） |
|------|------|------------------|
| Godot | 4.7.1 stable（mono 或标准版均可） | `C:\Users\60459\Tools\godot\Godot_v4.7.1-stable_mono_win64\` |
| Blender | 4.5 LTS 或更高（仅改模型时需要） | `C:\Users\60459\Tools\blender\blender-4.5.14-windows-x64\` |
| Git | 任意 | — |

**检查是否可用**：

```bash
godot --version          # 应输出 4.7.x
blender --version        # 应输出 Blender 4.5.x
```

如果 `godot` 不在 PATH 里，用完整路径代替。本文档后续的所有命令
都用 `godot` 代指可执行文件。

## 二、最快启动方式

```bash
cd <项目根目录>

# 首次需要导入资源（约 30 秒）
godot --headless --editor --quit

# 启动游戏
godot
```

启动后会看到主菜单，点「**单机开始（含 Boss 战）**」即可进入战斗。

> 如果主菜单文字显示成方块：说明系统缺少中文字体。
> 游戏会回退找 `C:/Windows/Fonts/msyh.ttc`（微软雅黑），
> Windows 上一般都有。若不是 Windows 或字体缺失，
> 请修改 `scripts/ui/main_menu.gd` 的 `_apply_font()`。

## 三、操作说明

### 基础操作

| 操作 | 按键 |
|------|------|
| 移动 | `W` `A` `S` `D` |
| 转视角 | 鼠标移动 |
| 冲刺跑 | 按住 `Shift` + 方向 |
| 跳跃 | `V` |
| **闪避翻滚** | `Space` |
| 轻攻击（三段连招） | `J` 或 鼠标左键 |
| 重攻击（可蓄力） | `K` 或 鼠标右键 |
| **锁定 / 解除锁定** | `Q` 或 鼠标中键 |
| 切换锁定目标 | 鼠标滚轮上/下 |
| 处决（目标破防时） | `F` |
| 打开 / 关闭调试面板 | `F3` |
| 显示鼠标指针 | `Esc` |

### 战斗要点（新手必看）

1. **精力是核心资源**。屏幕左上角（调试面板）能看到精力条。
   精力见底会进入「气竭」，恢复变慢。出招前想一下
   「再来一刀，还够不够滚？」

2. **收招阶段才是你的机会**。Boss 每招打完都有 0.95 秒以上的
   收招时间，这是唯一安全的输出窗口。它出招时你要做的是
   躲开，不是硬拼。

3. **闪避的无敌窗口是 0.06~0.36 秒**。要在 Boss 的刀快砍到你时
   才翻滚，滚早了会在无敌帧结束后被打中。

4. **重击更省精力**。破防 Boss 需要削 160 点架势：
   轻击每下 10 点（要 16 下），重击每下 34 点（只要 5 下），
   居合满蓄 50 点（只要 4 下）。但重击更慢、破绽更大。

5. **架势条打空可以处决**。Boss 架势被打破会跪地，
   这时会有一条红字提示「可处决」。靠近并按 `F`，
   造成 260 点伤害（是轻击的 14 倍）。这个窗口只有 3.5 秒。

6. **地形是你的武器也是掩体**。石柱能挡住 Boss 的冲锋，
   但打碎它就能开出一条侧翼路线。这是你自己的选择。

### 训练木桩

出生点右侧有两个训练木桩。它们的攻击起手 0.65 秒（很慢），
伤害只有 12 点。**用它们来熟悉连招、闪避和精力管理**，
死了也没关系。

## 四、四种武器原型与首个标志武器

任务要求提出三种低成本武器原型并选定一种。设计对比与选定理由
见 `docs/技术决策.md` 的 TD-001，简要结论：

| 原型 | 制作成本 | 辨识度 | 战斗深度 | 结论 |
|------|----------|--------|----------|------|
| 单手直剑 | 低 | 中 | 中 | 太"标准"，没有记忆点 |
| 双手巨剑 | 中 | 高 | 中高 | 蓄力只是"更慢更疼"，测不出位移配合 |
| **太刀** | **低（刀身只需 3 个盒子）** | **高（细长刀身 + 居合姿态）** | **高（进退拉锯）** | **选用** |

太刀的攻击集：

| 动作 | 起手 | 有效 | 收招 | 伤害 | 精力 | 说明 |
|------|------|------|------|------|------|------|
| 轻击·一之太刀 | 0.30 | 0.10 | 0.34 | 18 | 16 | 随手就能出 |
| 轻击·二之太刀 | 0.26 | 0.10 | 0.36 | 21 | 17 | 略快，连招有加速感 |
| 轻击·三之太刀 | 0.42 | 0.14 | 0.52 | 30 | 24 | 明显更重，收招最长 |
| 重击·蓄力斩 | 0.55 | 0.14 | 0.60 | 45 | 32 | 按住 K 可蓄力 0.85 秒 |
| 重击·居合（满蓄） | 0.22 | 0.16 | 0.74 | **80** | 32 | 9 m/s 突进，打空就是大破绽 |
| 闪避攻击·突进斩 | 0.20 | 0.10 | 0.46 | 24 | 20 | 闪避后段按攻击触发 |
| 处决·一閃 | 0.50 | 0.10 | 0.75 | **260** | 0 | 需先打破目标架势 |

**为什么居合的收招是 0.74 秒**：它是伤害最高的普通攻击
（单位风险收益最好），所以必须有最大的惩罚。这就是
"高风险高回报"的具体实现，不是嘴上说说。

## 五、联机（最多四人）

首版是**局域网主机模式**：一台机器创建房间，其他机器输入 IP 加入。
不做公网匹配、账号系统、专用服务器。

### 主机

1. 启动游戏
2. 在主菜单点「**创建房间（本机作为主机）**」
3. 记下界面显示的本机 IP（形如 `192.168.x.x`）
4. 告诉其他玩家这个 IP

### 其他玩家

1. 启动游戏
2. 点「**加入房间…**」
3. 输入主机的 IP
4. 点「连接」

端口固定为 `27015`。如果主机提示"端口被占用"，
说明有另一个程序在用这个端口（也可能是上一次的进程没退干净）。
可以修改 `scripts/net/net_manager.gd` 的 `PORT` 常量。

### 如何在没有多台机器的情况下测试

项目提供了自动化脚本，会在**同一台机器上开多个 Godot 进程**：

```bash
# 两人
bash tests/run_mp_battle_test.sh 2

# 四人
bash tests/run_mp_battle_test.sh 4
```

脚本会自动：启动主机 → 依次启动 3 个客户端 → 每个进程进入战斗关卡
→ 检查玩家/Boss/地形状态一致性 → 输出结果。

**这个测试能验证什么**：同步逻辑、权限分配、状态一致性、
地形破坏的跨端同步。

**这个测试不能验证什么**：真实网络延迟、丢包、NAT、
不同性能机器导致的时间差。

**跨设备测试的完整步骤**见 `docs/测试记录.md` 第五节。

## 六、调试工具

游戏中按 `F3` 打开调试面板（默认开启）。它显示：

- **玩家状态**：当前动作（待机/攻击/闪避/受击硬直…）与持续时间
- **攻击时序条**：用颜色区分起手（蓝）/ 有效判定（红）/ 收招（黄），
  这是调手感时最有用的信息
- **生命 / 精力 / 架势**：三条文本进度条
- **命中停顿**：触发时会显示
- **锁定目标**：以及目标是否处于可处决状态
- **Boss 状态**：血量、架势、当前招式、**招式权重表**
- **网络**：模式（主机/客户端）、玩家数、RTT
- **统计**：关卡阶段、用时、死亡次数、累计伤害

## 七、调参指南

所有手感参数都集中在两处，改完立刻能看到效果。

### 全局参数：`scripts/core/game_config.gd`

这个文件里每一项都有注释说明"改它会影响什么"。
常用的：

| 想要的效果 | 改哪个 |
|------------|--------|
| 走路/跑步速度 | `MOVE_SPEED` / `SPRINT_SPEED` |
| 闪避距离与无敌窗口 | `DODGE_DISTANCE` / `DODGE_IFRAME_START` / `DODGE_IFRAME_END` |
| 打击感（顿帧） | `HITSTOP_LIGHT` / `HITSTOP_MEDIUM` / `HITSTOP_HEAVY` |
| 镜头抖动强度 | `SHAKE_LIGHT` / `SHAKE_MEDIUM` / `SHAKE_HEAVY` |
| 精力够不够用 | `STAMINA_MAX` / `STAMINA_REGEN` / `STAMINA_REGEN_DELAY` |
| 破防难度 | `ENEMY_POISE_MAX` / `BOSS_POISE_MAX` / `POISE_REGEN` |
| 输入感觉迟钝 | `INPUT_BUFFER_TIME` / `DODGE_BUFFER_TIME` |
| 碎片太多卡顿 | `MAX_DEBRIS_RIGIDBODIES` / `DEBRIS_LIFETIME` |

**改完直接重启游戏即可生效**（`GameConfig` 是 Autoload，
改的是导出变量的默认值）。

### 武器参数：`tools/generate_weapons.gd`

每种攻击的 `windup` / `active` / `recovery` / `damage` /
`hit_offset` / `hit_radius` 等都在这里。

**改完必须重新生成**：

```bash
godot --headless --script tools/generate_weapons.gd
```

### 地形参数：`tools/build_scenes.gd`

石柱每段的 `max_durability` / `required_weight`、墙体的砖块布局等。

**改完必须重新构建场景**：

```bash
godot --headless res://tools/builder.tscn
```

### Boss 参数

Boss 的血量、架势、阶段阈值、冷却等都是**导出属性**，
可以直接在 Godot 编辑器里打开 `scenes/enemy/boss_arena.tscn`，
选中根节点在检视面板里改。

## 八、替换美术资源

当前的美术由两个 Blender 脚本生成：

| 脚本 | 产出 | 用途 |
|------|------|------|
| `tools/blender_assets.py` | 静态网格（`player.glb`、`boss_greatsword.glb`…） | 没有动画时的占位美术 |
| `tools/blender_rig.py` | **骨骼 + 14 个动画**（`player_rigged.glb`） | 主角实际使用的模型 |

```bash
# 重新生成静态模型
blender --background --python tools/blender_assets.py

# 重新生成骨骼动画主角
blender --background --python tools/blender_rig.py

# 加 --preview 会额外渲染关键帧拼图到 assets/preview/，
# 用于人工核对姿态（强烈建议加，否则改了姿态看不到效果）
blender --background --python tools/blender_rig.py -- --preview
```

场景生成脚本会**优先使用 `player_rigged.glb`**，
找不到才回退到静态的 `player.glb`，再找不到才用几何体占位。

然后重建场景：

```bash
godot --headless res://tools/builder.tscn
```

### 建模时必须注意的两件事

1. **朝向**：模型要面向 **Blender 的 +Y**。
   因为 glTF 导出会做 `Godot.z = -Blender.y` 的转换，
   只有朝 +Y 才能在 Godot 里得到正确的 -Z 前向。
   搞反会让角色背对镜头、武器挂在背后。
   校验方法：`godot --headless res://tests/test_models.tscn`

2. **原点与比例**：单位用米。角色原点在脚底，Boss 高 3.2 m，
   石柱高 4.3 m。换模型后必须重新检查碰撞体尺寸是否仍然匹配，
   并跑一次战斗测试确认攻击范围没失效。

### 场景生成脚本的占位机制

`tools/build_scenes.gd` 会**优先使用 GLB**，GLB 不存在时
回退到几何体占位。所以即使没跑过 Blender 脚本，
项目也能构建出可运行的版本。这对新环境上手很有用。

### 已经完成的东西

- **骨骼动画**：主角 21 根骨骼 + 14 个动画（待机/跑/三段连招/重击/
  居合/闪避攻击/处决/闪避/轻受击/重受击/破防/死亡）。

  接口已接线（攻击/命中/死亡/破防都会触发）。

  连续破坏）的自动化测量，含上限探针。结论：碎片池上限 60 有余量约 30 倍。
- **联机同步**：位置、动画、Boss 状态、地形破坏全部打通并实测。

### 明确的缺口

- **未做跨设备联机实测**。所有联机验证都在同一台机器上用多进程完成。
  真实网络延迟、丢包、NAT 的表现未验证。
  → 步骤已写在 [docs/跨设备测试指南.md](docs/跨设备测试指南.md)。
- **无动画混合**（没有 AnimationTree）。动作之间是硬切，没有
  0.1~0.2 秒的过渡。观感可以接受，但不够顺滑。
- **动画是程序生成的关键帧**。姿态由脚本算出，缺少手工打磨的细节
  （预备动作、惯性余韵）。可用，但达不到动画师手工调的水准。
- **未做长时间稳定性测试**（10 分钟级的运行与内存增长）。

## 十二、遇到问题怎么办

| 现象 | 原因与处理 |
|------|------------|
| 主菜单中文显示成方块 | 缺少中文字体，见第二节的说明 |
| 「创建房间」报端口被占用 | 有程序占用了 27015，或上次的进程没退干净。改 `net_manager.gd` 的 `PORT` |
| 「加入房间」连不上 | 确认主机已创建房间、IP 输入正确、两台机器在同一网段、防火墙允许 Godot 通过 |
| 改武器数值后没生效 | 需要重跑 `godot --headless --script tools/generate_weapons.gd` |
| 改地形数值后没生效 | 需要重跑 `godot --headless res://tools/builder.tscn` |
| 模型没换成功 | 确认 `assets/models/*.glb` 存在；场景生成脚本会在 GLB 缺失时回退到几何体占位 |
| 角色背对镜头 / 武器在背后 | 模型朝向错了，要面向 Blender 的 +Y，见第八节 |
| 脚本报 `Identifier not found: GameConfig` | 用 `--script` 模式运行时不会加载 Autoload。改用 `godot --headless res://tools/builder.tscn` 这种场景方式 |
| 角色没有动画，像在滑步 | 模型回退到了静态版。确认 `assets/models/player_rigged.glb` 存在，再跑一次 `godot --headless res://tools/builder.tscn` |
| 攻击打出去了但刀还没挥到 | 动画时长与战斗配置不同步。跑 `tests/animation_test.tscn` 的 A2 项检查 |
| 联机时队友在滑步不挥刀 | 动画同步没生效。跑 `tests/sync_debug.tscn` 看链路计数（见该文件顶部说明） |
| 没有声音 | 确认 `assets/audio/*.wav` 存在；跑 `tests/audio_test.tscn` 的 S1 项 |
| 性能测试报"渲染指标为 0" | 正常。无头模式用 dummy 渲染器，渲染侧指标恒为 0，只测 CPU 逻辑与物理 |
| 攻击打不中 | 先跑 `test_runner.tscn`。如果 T13 失败说明朝向约定被改动了 |
| 控制台刷 `Node not found ... Requested node was not found` | 联机时主机在对端节点未就绪前发了 RPC。见 `docs/测试记录.md` 的问题 9 |
