# 项目计划

低多边形 3D 类魂合作沙盒战斗 Demo。本文说明阶段划分、交付目标与验收方式。

---

## 一、项目定位

**这是一个玩法验证 Demo，不是完整游戏。**

第一版严格限定为 8 项核心内容（见任务书第三节）：
可玩主角、三种武器（首版实装一种）、小型 3D 战斗场景、一个有攻击模式的 Boss、
高质量基础战斗操控、可破坏地形、最多四人合作、生命/精力/受击/死亡/复活。

**明确不做**：Galgame 剧情、完整多武器系统、开放世界生成、
复杂采集建造、完整角色成长系统。

**最高优先级永远是战斗手感**，优先级高于场景规模、剧情数量和装饰精度。

### 阶段 B：核心战斗原型 ✅ 已完成

**交付目标**
- 主角移动、镜头、锁定
- 标志武器（太刀）的完整攻击集
- 攻击判定、闪避、精力、受击、命中反馈

**验收标准（任务书阶段 B）**：
> "此阶段结束时，必须能够在游戏中亲自操作主角并完成基本战斗。"

**验收方式**
1. 启动游戏，用 WASD + 鼠标移动与转视角
2. 用 J / 鼠标左键打出三段连招，观察节奏差异
3. 长按 K / 鼠标右键蓄力，观察居合的突进
4. 空格闪避，观察无敌帧与位移
5. 对训练木桩战斗，观察伤害数字、硬直、架势条变化
6. 按 F3 查看攻击时序条是否正确显示起手/有效/收招

### 阶段 C：Boss 与地形破坏 ✅ 已完成

**验收方式**
1. 从出生点走向 Boss（约 20 m）
2. 观察 Boss 的三种以上攻击、地面预警圆、阶段切换
3. 打掉东侧石柱，确认侧翼路线的阻挡物消失
4. 打掉中央墙体，确认战场中央出现通道
5. 击败 Boss（血量 60% 进入二阶段），观察胜利反馈

## 四、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 没有正式角色动画 | 战斗手感无法达到最终标准 | 用代码驱动的姿态变化 + 硬直倾斜做占位；动画缺口在 `测试记录.md` 中明确标注 |
| 没有专业录音级音效 | 音频表现上限有限 | 已用 `tools/generate_audio.py` 离线合成 14 个音效 + Boss 环境氛围并接入总线混响/压缩；文件缺失时自动回退到运行时合成占位音 |
| Boss 位置未同步 | 联机时客户端看不到 Boss 移动 | 阶段 D 待办，已记录在 `架构说明.md` 5.5 |
| 无法在本环境实测四人 | 验收标准 7、8 无法确认 | 不虚构测试结果，提供可重复执行的四人测试步骤 |
| 敌人 AI 无仇恨系统 | 高人数下可能仍偏向单体 | 已用权重表 + 概率换目标缓解；完整方案写入 `战斗设计.md` 7.5 |
