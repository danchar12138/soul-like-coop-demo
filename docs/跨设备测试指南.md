# 跨设备联机测试指南

本文说明如何在**多台机器**上验证四人合作，以及要观察什么。

配套脚本：[tests/run_lan_test.sh](../tests/run_lan_test.sh) 与
[tests/lan_test.gd](../tests/lan_test.gd)

---

## 一、为什么必须做跨设备测试

项目已经有 `tests/run_mp_battle_test.sh`，它会在**同一台机器**上开
最多 4 个 Godot 进程。那个测试能验证：

- 同步逻辑是否正确
- 权限分配是否正确
- 状态是否一致（玩家列表、Boss、地形）

但它**测不出任何与时序相关的问题** —— 同一台机器上回环延迟几乎为零
（实测 RTT 12~16 ms，其中大部分还是 Windows 内核计时器粒度带来的
量化误差，不是真实网络往返）。

跨设备测试才能暴露：

| 会暴露的问题 | 为什么单机多进程测不出 |
|--------------|------------------------|
| 位置插值在真实延迟下是否平滑 | 延迟为 0 时插值永远是准的 |
| 动画进度同步是否准确 | 用到的是引擎时间，两端在同一进程族里时钟一致 |
| Boss 位置同步的滞后是否可接受 | 20Hz 同步的滞后在 0 延迟下看不出来 |
| 地形破坏的广播延迟 | 同上 |
| 不同性能机器之间的状态漂移 | 单机多进程共享同一套时钟与调度 |

## 二、准备

### 网络要求

所有机器在**同一个局域网**（同一路由器 / 同一 WiFi / 同一交换机）。
不需要联网，不需要公网 IP。

### 防火墙

Windows 首次运行 Godot 监听端口时会弹防火墙提示，选**允许**
（专用网络即可）。如果误点了"取消"，需要手工在
"Windows Defender 防火墙 → 允许应用通过防火墙"里加上
`Godot_v4.7.1-stable_mono_win64.exe`。

### 端口

固定使用 `27019`（跨设备测试）与 `27015`（实际游戏）。
如果被占用，改 `tests/lan_test.gd` 的 `TEST_PORT`
或 `scripts/net/net_manager.gd` 的 `PORT`。

## 三、执行

### 第一步：主机

在**一台**机器上：

```bash
cd <项目根目录>
bash tests/run_lan_test.sh host
```

输出里会显示本机局域网地址，例如：

```
[跨设备] 房间已创建，端口 27019
[跨设备] 本机局域网地址：192.168.10.50
[跨设备] 请在客户端上执行：
[跨设备]   bash tests/run_lan_test.sh client <上面的地址>
```

**记下这个地址。** 如果显示"未检测到"，在主机上执行 `ipconfig`，
找 `IPv4 地址`那行（通常是 `192.168.x.x` 或 `10.x.x.x`）。

### 第二步：客户端

在**其他每台**机器上（把 IP 换成上一步显示的）：

```bash
cd <项目根目录>
bash tests/run_lan_test.sh client 192.168.10.50
```

脚本会连上并自动进入战斗关卡，然后跑 60 秒：
- 每 2 秒采集一次 RTT
- 每 1 秒采样一次远端玩家的位置与动画
- 每 3 秒自动出一次招（这样"远端动画同步"这条路径才会被走到）
- 第 30 秒强制 Boss 仇恨（让它动起来）
- 第 60 秒打印观测报告

**四人的话，在另外两台机器上重复第二步。**

> 建议先做**两人**测试。两人通过之后再上四人 ——
> 出问题时更容易定位是哪一端的问题。

## 四、要观察什么

### 脚本能自动给出的客观指标

| 指标 | 合格范围 | 说明 |
|------|----------|------|
| RTT 平均值 | < 20 ms（局域网） | 20~60 ms 可接受；> 60 ms 位置同步会有明显滞后感 |
| 会话期间最大玩家数 | = 参与人数 | 少了说明有人的玩家实体没生成 |
| 观测到远端玩家位置变化 | > 0，且越多越好 | 为 0 说明位置同步没在工作 |
| 观测到远端玩家动画切换 | > 0 | 为 0 说明动作同步没在工作 |

### 必须人工确认的项（脚本无法判定）

这些**必须真人在带显示器的机器上看**。脚本只能把清单打出来。

- [ ] **1. 其他玩家的移动是否平滑** —— 不应该有明显的跳动或拖影。
      有跳动说明插值参数需要调（`PlayerSync.INTERP_SPEED`）。
- [ ] **2. 其他玩家挥刀时刀是否在动** —— 应该能看到队友的刀在挥。
      如果队友是"平移着滑过去"，说明动画同步没生效。
- [ ] **3. Boss 移动是否可接受** —— 20Hz 同步 + 插值，
      **快速移动时能看到轻微滞后是正常的**（设计取舍，见架构说明 5.2）。
      但如果 Boss 一直在"瞬移"，那就是 bug。
- [ ] **4. 自己操作是否有延迟感** —— 应该**没有**。
      玩家位置是客户端权威（见技术决策 TD-008），
      自己的移动不该等服务器回包。如果有延迟感，说明权威分配错了。
- [ ] **5. 打碎石柱后，多久能在对端看到它消失** —— 应 < 0.5 秒。
      局域网下通常几乎同时。
- [ ] **6. 四个玩家同时打同一根石柱时，各端结果是否一致** ——
      石柱应该在**所有机器上**同时或几乎同时消失，
      不能出现"A 端碎了 B 端还在"。

### 第 5、6 项的手工做法

这两项需要人操作，脚本不自动做（它会自动出招，但不会专门去拆石柱）：

1. 走到东侧石柱（出生点向右前方约 11 米）
2. 用重击（`K` 长按蓄满）打石柱，约 3 下打碎一根
3. 四人一起打同一根，观察各端

## 五、已知会在跨设备下表现不佳的项

**提前说明，避免误判为 bug。**

| 现象 | 原因 | 是否要修 |
|------|------|----------|
| Boss 快速跑动时位置略滞后 | 只广播位置不广播速度，20Hz + 插值的固有滞后 | 不需要。想改善可以做速度预测，但当前观感可接受 |
| 远端玩家急停时有一点点"滑" | 插值速度固定（`INTERP_SPEED = 14`） | 可选。可以按距离自适应 |
| 远处玩家的攻击音效听不太清 | 3D 音效的 `max_distance = 32 m` 衰减 | 设计如此 |
| 远端玩家的受击闪白略晚 | 受击表现不走网络，各端按自己收到的伤害事件播 | 不需要 |
| 地形破坏在客户端比主机晚一点看到 | 主机权威，客户端等广播（见 TD-007） | 不需要，一个 RTT 内 |

**如果出现下面这些，那才是真 bug，请记录并反馈：**

- 某台机器上的玩家数量与其他机器不同
- 某台机器上的 Boss 血量与其他机器不同（应该完全相同）
- 石柱在某台机器上碎了、在另一台上还在
- 自己的操作有延迟感
- 玩家位置出现"橡皮筋"（被服务器拉回去）

## 六、结果记录

把两端脚本输出的观测报告贴到 `docs/测试记录.md` 的
"跨设备测试"一节，并如实标注：

- 参与机器数与各自的配置
- RTT 实测值
- 六项人工确认项的实际结果
- 未通过或存疑的项

**不要只写"测试通过"。** 跨设备测试的价值在于人工观察到的细节 ——
"通过"两个字会把最有价值的信息丢掉。
